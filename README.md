# TS6 Droid Русская версия

Android-клиент на основе открытого проекта автора [flamme-demon/TS6_Droid](https://github.com/flamme-demon/TS6_Droid), с Русификацие и расширенным функционалом.

Это свободный, лёгкий Android-клиент TeamSpeak 3/6, построенный на Jetpack Compose, работающий на базе `tslib`, написанного на Rust.

## Список изменений

### v2.1.8-Han (2026-10-20)

**Добавлено: онлайн / отошёл / не беспокоить (меню статуса как в десктопном клиенте)**

- В крайней левой части нижней панели добавлен **индикатор статуса** (зелёный = онлайн, янтарный = отошёл, красный = не беспокоить), по нажатию открывается меню статуса
- **Онлайн**: снимаются отметка «отошёл» и сообщение об отсутствии
- **Отошёл**: устанавливаются отметка «отошёл» и сообщение об отсутствии, микрофон работает как обычно
- **Не беспокоить**: помимо отметки «отошёл» **микрофон отключается**, удержание для разговора / удержание для шёпота / открытый микрофон не могут включить микрофон;
  при переключении обратно в онлайн или «отошёл» микрофон восстанавливается согласно текущему режиму
- **Пользовательское сообщение об отсутствии**: заполняется прямо в меню (до 100 символов), при пустом поле используется текст по умолчанию (отошёл / не беспокоить)
- В панель по **долгому нажатию на свою строку** добавлены строка «Статус» и кнопка «Изменить статус»
- В панель по **долгому нажатию на любого участника** добавлены две строки — «Статус» и «Сообщение об отсутствии»
- После переподключения при обрыве выбранный статус автоматически восстанавливается, сбрасывается в онлайн только при主动 отключении

**Исправления**

- **Переключение статуса не отображалось у других клиентов**: при переключении статуса отправлялась только одна команда, быстрые нажатия объединялись, между командами выдерживался минимальный интервал,
  больше не срабатывает ограничение сервера от флуда (`client is flooding`) с потерей команды; если всё же сработало ограничение, через 10 секунд команда автоматически отправляется повторно
- **В плавающем окне нельзя было ввести пароль для канала с паролем**: при открытии поля пароля окну временно разрешается получить фокус и показать клавиатуру,
  после закрытия сразу восстанавливается (ранее это окно не могло получить фокус, и клавиатура не появлялась)
- **Состояние отключения микрофона**: сообщается только при реальном изменении состояния, и использует тот же минимальный интервал, что и команды статуса, поэтому быстрое удержание / отпускание для разговора тоже не вызывает ограничения от флуда

**Низкий уровень**

- В `tslib_multi` 8e0bc11 добавлен патч
  [`patches/tslib_multi-8e0bc11-away-status.patch`](patches/tslib_multi-8e0bc11-away-status.patch)
  (накладывается поверх патча шёпота из v2.1.7): в `tslib-core` добавлен `set_away`, в `tslib-jni` добавлен `nativeSetAway`
  - Патч в репозитории имеет окончания строк LF; если в рабочей копии на Windows с `core.autocrlf=true` при применении возникает ошибка
    `different line endings`, сначала выполните `dos2unix` для файла патча (или `patch --binary`), затем применяйте
- Нативная библиотека пересобрана кросс-компиляцией (arm64-v8a, `--features vendored-openssl`)
- Модульные тесты 75 → 79

### v2.1.7-Han (2026-10-19)

**Шёпот (Whisper) — голосовой шёпот с семантикой десктопного клиента вернулся**

В v2.1.5 «Шёпот» был удалён, потому что та реализация умела отправлять только текстовые личные сообщения: для голосового шёпота нижний уровень `tslib` должен упаковывать захваченные пакеты в `C2SWhisper`, а в поставлявшейся нативной библиотеке этого интерфейса не было. В этот раз нативная библиотека заменена на сборку с интерфейсом шёпота (`tslib_multi` 8e0bc11) и дополнены UI и конечный автомат:

- **Голос отправляется только целям (маршрутизация при удержании)**: сам список шёпота **не** переводит микрофон в постоянный режим шёпота — голос по умолчанию идёт как обычно в текущий канал, и только при **удержании кнопки шёпота** захваченные пакеты нативным слоем упаковываются в пакеты шёпота и отправляются целям (клиент / весь канал / вся серверная группа), при отпускании всё сразу восстанавливается. Так семантика двух микрофонов в нижней панели не конфликтует: обычный микрофон — в канал, микрофон шёпота — в список
- **Два микрофона «удержание для шёпота»**: слева от основного микрофона в нижней панели добавлен янтарный микрофон (со значком шёпота), такая же кнопка добавлена в панель плавающего окна, **долгое нажатие для разговора — это шёпот**, без предварительного переключения какого-либо режима; при пустом списке выдаётся подсказка сначала добавить цели, а не молчаливое бездействие. При удержании **сначала переключается маршрут, затем включается микрофон** (микрофон открывается только после готовности нативного набора), поэтому начало фразы не утекает в канал; при отпускании **сначала выключается микрофон, затем снимается маршрут**. Состояние микрофона до нажатия (голосовая активация / открытый микрофон / удержание для разговора) восстанавливается как было
- **Шёпот в серверную группу (нативная маршрутизация протокола)**: в `tslib` добавлен канал групповых целей — `set_whisper_targets` принимает `groups: Vec<u64>`, отправка идёт по **пакету группового шёпота** протокола 1.8.2.1 (`VoiceWhisper` + флаг `Newprotocol` + `GroupWhisperType::ServerGroup` + `GroupWhisperTarget::AllChannels`), **состав группы разбирает сервер**. Поэтому группа считается за одну цель, участники, **присоединившиеся позже, тоже сразу слышат**, при входе/выходе участников, изменении группы и переподключении при обрыве приложению не нужно рассылать заново; не нужно и раскрывать группу в клиентский список (это упиралось бы в клиентский лимит целей)
- **Имена пользовательских групп**: после установления соединения нативный слой отправляет серверу `servergrouplist`, список имён групп возвращается через `nativeGetServerGroups()`, в списке шёпота отображаются настоящие имена групп (при неудаче — откат к «Пользовательская группа #id»)
- **Видимость пользовательских групп участника**: в панели, открываемой долгим нажатием на любого участника (**включая свою строку**), добавлен раздел «Серверные группы», где по именам групп, возвращённым сервером, перечислены группы участника (если имя не получено — показывается `Пользовательская группа #id`, при большом числе групп раздел прокручивается отдельно); в своей строке отображаются только идентификация и информация о группах, операции громкость/отключение звука/личные сообщения/шёпот, бессмысленные для себя, скрываются
- **Видимость канальных групп участника**: в той же панели есть строка «Канальные группы» (канальные группы, которые участник имеет в текущем канале), имена групп берутся из `channelgrouplist` сервера (нативный слой запрашивает при подключении, обновляет при открытии панели); при неудаче показывается `Канальная группа #id`, при отсутствии номера группы (0) вся строка скрывается, а не показывается 0
- **Панель списка шёпота**: иконка шёпота в верхней панели открывает редактор списка, разделённый на три раздела с чекбоксами — «Серверные группы / Каналы / Участники», в строке группы отображается число онлайн (только для справки, групповые цели не занимают клиентские места)
- **Список шёпота**: справа в строке участника добавлена кнопка шёпота (зелёная = уже в списке), переключатель есть и в панели по долгому нажатию на участника; долгое нажатие на строку канала добавляет / убирает **весь канал**, строки каналов в списке показывают зелёный значок шёпота
- **Верхний предел записей целей — 10**: считается по записям шёпота (значение по умолчанию серверного `virtualserver_maxwhisperclients`), клиент / канал / пользовательская группа считаются каждая за одну запись; при превышении панель выдаёт подсказку, а не молчаливый сбой
- **Архивирование по UID**: цели шёпота и сеансы личных сообщений используют один и тот же ключ сеанса (`PrivateConversations.keyFor`), после переподключения собеседника цель остаётся действительной; **после автоматического переподключения при обрыве список автоматически рассылается заново**, не нужно заново всё отмечать
- **Офлайн-цели не раскрываются**: когда все цели офлайн, отправляется «сторожевой сигнал отбрасывания» (клиент 0), пакеты шёпота сервер просто отбрасывает; никогда не выполняется откат к широковещанию в канал, иначе в интерфейсе было бы написано «шёпот», а слышал бы весь канал
- **Индикация шёпота**: зелёная иконка шёпота в верхней панели (список настроен), баннер «Список шёпота: …» и текст-заполнитель над полем ввода чата, при удержании шёпота вокруг своего аватара появляется **янтарное** свечение (рамка пузыря плавающего окна также становится янтарной), когда кто-то шепчет вам, один раз показывается подсказка (защита от повторов 15 секунд)
- **Текст отправляется в список**: когда список шёпота не пуст, введённый текст отправляется личными сообщениями каждой онлайн-цели (групповые цели — онлайн-участникам группы в данный момент) и как обычно архивируется в сеанс личных сообщений; цели-каналы получают только голос (в TS3 нет текстовой команды для произвольного канала)

**Добавлено: смена временного никнейма в канале**

Долгое нажатие на свою строку → «Изменить временный никнейм» внизу панели → ввод нового никнейма (проверка 3–30 символов, те же правила, что на странице подключения) → через `clientupdate client_nickname` применяется сразу, список участников тут же показывает новый никнейм.

- **Действует только для текущего соединения**: файл идентификации не меняется, после переподключения возвращается никнейм, использованный при подключении (нативный слой запоминает обновлённый никнейм в памяти как локальное переопределение — сервер не возвращает `clientupdate` отправителю, иначе список участников показывал бы старое имя)
- Если никнейм отклонён сервером (дубликат/запрещённые символы), это по-прежнему反馈 через ошибку сервера

**Попутно исправлено: вход в канал с паролем**

Ранее при нажатии на канал, требующий пароля, происходил только отказ на сервере: интерфейс не показывал подсказку и не переключался — выглядело как «нажал — и ничего не происходит» (нативный `moveToChannel(channelId, password)` на самом деле早已 был, не хватало только клиентского входа).

- В строке канала отображается **иконка замка**, пароль виден ещё до нажатия
- По нажатию открывается **поле ввода пароля** (стеклянный диалог + маскировка пароля), после подтверждения вход в канал выполняется с паролем
- Пароль **не сохраняется**, используется только для этого входа; при ошибке пароля по-прежнему反馈 через ошибку сервера
- **Список каналов плавающего окна обрабатывается так же**: встроенный ввод пароля в списке + иконка замка (плавающее окно — это окно с `WRAP_CONTENT`, полноэкранный диалог был бы обрезан, поэтому здесь используется встроенный ввод, а не диалог)

**Низкий уровень**

- Нативная библиотека собрана самостоятельной кросс-компиляцией на основе `tslib_multi` 8e0bc11 (**этот коммит не в upstream main, это личный коммит для сборки в CI**) **с патчем**, патч см. в [`patches/tslib_multi-8e0bc11-whisper-groups.patch`](patches/tslib_multi-8e0bc11-whisper-groups.patch) (`git apply` к 8e0bc11 применяется чисто): он добавляет в `tslib-core` отправку пакетов группового шёпота `whisper_groups`, `set_nickname` (`clientupdate client_nickname` + локальное переопределение), запросы `servergrouplist` / `channelgrouplist` и чтение имён групп, а для JNI добавляет `nativeGetServerGroups`, `nativeGetChannelGroups`, `nativeSetNickname` и трёхпараметрический `nativeSetWhisperTargets`; прилагаемые 6 модульных тестов фиксируют по документации протокола байтовую раскладку пакета группового шёпота и правило маршрутизации «все офлайн — без отката в канал»
- Пересборка (WSL + Linux NDK r27c + cargo-ndk, `ANDROID_NDK_HOME` указывает на NDK): `cargo ndk -t arm64-v8a --platform 29 -o <out> build --release -p tslib-jni --features vendored-openssl` (`vendored-openssl` нельзя опускать: `reqwest`/`native-tls` потянут `openssl-sys`)
- Попутно появляются интерфейсы `nativeSetWhisperTargets` / `nativeSetAudioSink` / `nativeWaitEvents` / `nativeSendPoke` / `nativeGetNetworkStats` и др. (в этот раз подключена только часть, необходимая для шёпота)
- **Исправлены два расхождения сигнатур JNI**: в `nativeMoveToChannel` добавлен параметр пароля канала, в `OpusCodec.nativeDecode` добавлен параметр FEC. Без первого читался бы несуществующий параметр, без второго мусорное значение передавалось бы в нативный слой как флаг
- Приём голоса переведён на **push-модель**: нативный слой передаёт каждый пакет напрямую колбэку `AudioBridge` (это единственное место, где можно отличить «пакет шёпота» от «пакета канала»), событийный путь воспроизведения `audio_received` вместе с этим удалён во избежание двойного воспроизведения
- Модульные тесты 46 → 75 (список и маршрутизация целей шёпота, проброс групповых целей, ключи сеансов, именование пользовательских/канальных групп, правила никнейма)

### v2.1.6-Han (2026-10-17)

> В этом обновлении учтён проект [wslinnn/TS6_Droid_CN](https://github.com/wslinnn/TS6_Droid_CN).

**Размер установочного пакета: 71,7 MB → 14,9 MB**
- Включены сжатие кода и сокращение ресурсов R8, а также архивируется `mapping.txt` для восстановления обфусцированных стек-трейсов. Ранее release-пакет никогда не проходил через R8, около 11 400 неиспользуемых классов иконок Material попадали в пакет (dex 58,3 MB → 3,2 MB).

**Безопасность и приватность**
- **Проверка канала вложения**: параметр `channel` в ссылках `ts3file://` брался напрямую из текста сообщения. Ранее любой, отправив специально сформированное сообщение, мог заставить клиент запрашивать файлы **произвольного канала**; теперь сначала проверяется существование этого канала.
- **Встроенные изображения подчиняются переключателю**: ссылки `[img]`/изображений в чате ранее **обходили** настройку «Автозагрузка изображений» и загружались безусловно, раскрывая локальный IP-адрес серверу, указанному отправителем; теперь настройка соблюдается (по умолчанию отключена), загрузка — по нажатию.
- Параметры ссылок общего доступа переведены на URL-кодирование (имена файлов с китайскими символами, пробелами, `&` и т.п. больше не ломаются)
- Одноимённые файлы в разных каналах больше не используют общий кэш
- При фильтрации системных подсказок сообщения пользователей, содержащие те же слова, больше не проглатываются ошибочно
- **Облачный бэкап / перенос на новое устройство** исключают закладки (включая пароли серверов в открытом виде) и историю чатов; ранее исключался только приватный ключ идентификации
- **Пароль подписи больше не записывается в скрипт сборки**: теперь читается из переменных окружения или локального `keystore.properties` (см. [Пояснение о подписи сборки](#пояснение-о-подписи-сборки-на-нескольких-компьютерах))

**Стабильность**
- Сообщения с одинаковой миллисекундой в списке чата больше не вызывают краш из-за дублирования ключей LazyColumn
- Загрузка файлов теперь **сначала проверяет размер, затем читает**: при превышении 10 MB сразу выдаётся предупреждение, большие файлы больше не читаются целиком в память с OOM
- История чата переведена на разбор через `org.json`: ранее самописный сканер при встрече текста с `\"` **молча отбрасывал эту запись и всю историю после неё**
- Сообщение отзывается локально только при отказе сервера (ранее сбой любой команды мог ошибочно удалить успешно отправленные сообщения)
- Состояние «Говорит» больше не зависает навсегда; сообщения, приходящие в момент подключения, больше не теряются
- Загрузка аватаров, декодирование предпросмотра изображений, чтение при загрузке файлов вынесены из главного потока; убрано засорение логов отладочными сообщениями PermCheck
- При чанковой передаче установочного пакета сервером (общий размер неизвестен) прогресс обновления больше не застревает ошибочно на 100%

**Голос**
- **Микрофон с голосовой активацией**: режим микрофона расширен до выбора из трёх — «Удержание для разговора / Голосовая активация / Открытый микрофон», для голосовой активации поддерживается порог −70 ~ −15 dB, встроены гистерезис, задержка отпускания и буфер предотправки (не обрезаются начало и конец слов)
- **Усиление микрофона 0 ~ 400%** (0% — микрофон выключен), решает проблему «собеседник слышит меня тихо»
- **Громкость для каждого пользователя**: долгое нажатие на участника открывает панель, где можно отдельно регулировать громкость, отключать звук, отправлять личные сообщения; сохраняется по UID и действует между сеансами
- **Аудиофокус и эхоподавление**: при эксклюзивном аудио (входящий звонок, навигационные оповещения и т.п.) приложение автоматически уступает (при поддержке duck — снижается до 30%), после завершения автоматически восстанавливается без переподключения; при поддержке устройством автоматически подключается AEC, при громкой связи собеседник больше не слышит эхо
- На выходное усиление добавлен мягкий лимитер, при включённом усилении больше нет жёсткого клиппирования
- Пробуждение в период тишины воспроизведения 50 раз/с → 4 раза/с, снижено энергопотребление в простое без влияния на задержку начала воспроизведения
- Низколатентная голосовая дорожка при сбое инициализации на некоторых устройствах автоматически пересоздаётся без `PERFORMANCE_MODE`, больше нет отсутствия звука

**Сеть**

- Просмотр сетки миниатюр кэшированных обоев с поддержкой удаления по одному
- Очистка кэша сопровождается окном повторного подтверждения
- Все вышеперечисленные настройки доступны только при включённом «Я — отаку»

**Оптимизация анимированного фона**
- Переключение обоев больше не мерцает: механизм кэширования + анимация появления 600 мс
- Переключение страниц больше не вызывает повторную загрузку, все страницы используют одни и те же обои
- Пустой список на главной отображается по центру с надписью «Нет подключений»

**Предпросмотр изображений в файловом менеджере**
- Нажатие на файл изображения открывает полноэкранный предпросмотр прямо в приложении, больше не предлагается внешний способ открытия

## Русификация и расширенные возможности

1. **Локализация на Русский**: на 100% дополнен полный перевод на Русский (`zh-rCN`).
2. **Переключение языка**: поддержка переключения одним нажатием между Русским, Китайским, Английским, Французским, без изменения системного языка телефона.
3. **Встроенный основной голосовой драйвер**: напрямую встроена основная бинарная библиотека (`jniLibs`, в настоящее время в пакете поставляется только arm64-v8a), работает из коробки.
4. **Облегчённый установочный пакет**: в release-сборке включены сжатие кода и сокращение ресурсов R8, установочный пакет около **15 MB** (без сжатия около 72 MB).
5. **CI/CD**: облачная сборка с запуском модульных тестов; после пуша тега версии автоматически выполняется подписанная сборка и публикация Release.
6. **Единый матовый материал и собственные иконки**: карточки, плавающая нижняя панель, всплывающие окна, меню, панель участников и нижняя панель — это один набор «отрисовываемых на месте» полупрозрачных матовых поверхностей, следующих за системной тёмной/светлой темой; при отключении аниме-фона автоматически возвращаются к сплошной поверхности. Иконки интерфейса унифицированы в собственный набор `AppIcons`, иконки Material больше не смешиваются.
7. **Аниме-фон и пользовательский фон** (по умолчанию отключено): после включения можно получать онлайн аниме-обои и автоматически извлекать основной цвет для генерации темы, а также выбирать изображение из галереи (с предпросмотром кадрирования); для кэша обоев можно задать лимит, просматривать, удалять по одному и **экспортировать в галерею**.
8. **Фоновое плавающее окно**: после подключения при уходе приложения в фон появляется плавающий пузырь (при разговоре кого-либо отображается аватар говорящего, иначе — иконка приложения), можно перетаскивать, прилипает к краю экрана; лёгкое нажатие разворачивает панель с текущими участниками канала, переключением каналов, управлением микрофоном/звуком, отключением от соединения; долгое нажатие на пузырь — **удержание для разговора**, кнопка ⌂ в шапке — возврат в приложение одним нажатием.
9. **Автопереподключение при обрыве и поддержание работы в фоне**: после обрыва — автоматическое переподключение с экспоненциальной задержкой и возврат в исходный канал, при переключении WiFi / сотовой сети — мгновенное переподключение; предусмотрены быстрый доступ к белому списку оптимизации батареи и сведениям о приложении; во время соединения удерживается wake lock, работает сторожевой таймер микрофона для самовосстановления.
10. **Голосовое управление**: режим микрофона поддерживает «Удержание для разговора / Голосовая активация / Открытый микрофон», для голосовой активации регулируется порог; усиление микрофона 0 ~ 400%, выходное усиление 0 ~ 800% с мягким лимитером; поддержка отдельной регулировки громкости и отключения звука по каждому участнику (сохраняется по UID).
11. **Аудиофокус и эхоподавление**: при эксклюзивном аудио (входящий звонок, навигационные оповещения и т.п.) приложение автоматически уступает и автоматически восстанавливается без переподключения; при поддержке устройством автоматически включается AEC.
12. **Экспорт / импорт идентификации**: на странице настроек можно просмотреть UID идентификации, экспортировать / импортировать `identity.ini`, при смене устройства можно сохранить права на сервере.
13. **Карточка информации о сервере**: просмотр названия сервера, платформы / версии, числа онлайн, количества каналов, времени работы и приветствия.
14. **Файловый менеджер**: просмотр / скачивание / загрузка / создание / переименование / удаление / совместное использование, изображения можно просматривать в полноэкранном режиме внутри приложения.
15. **Обновление внутри приложения**: после проверки обновления скачивание и установка APK выполняются прямо в приложении, описание обновления поддерживает Markdown.
16. **Возможности диагностики**: оверлей отчёта о краше (при следующем запуске показывает стек-трейс с копированием одним нажатием) и просмотрщик логов внутри приложения (Настройки → Дополнительно → Журнал диагностики).
17. **Шёпот (Whisper)**: голосовой шёпот с той же семантикой, что у десктопного клиента — когда список шёпота (участники / весь канал / **вся серверная группа**, верхний предел 10 записей) не пуст, **удерживайте** янтарную кнопку шёпота рядом с микрофоном, и голос будет отправляться только целям из списка (при отпускании немедленно возвращается к разговору в канале, режим микрофона до нажатия восстанавливается как был); серверные группы отправляются пакетом группового шёпота протокола 1.8.2.1, **состав разбирает сервер** (группа считается за одну цель, участники, присоединившиеся позже, тоже сразу слышат); в нижней панели и в панели плавающего окна есть по микрофону «удержание для шёпота», при удержании сначала переключается маршрут, затем включается микрофон — начало фразы не утекает в канал; цели архивируются по UID, после переподключения при обрыве автоматически рассылаются заново, когда все цели офлайн, голос отбрасывается, а не откатывается к широковещанию в канал; баннер чата показывает текущий список шёпота, введённый текст отправляется личными сообщениями тем же адресатам, аватар говорящего становится янтарным.
18. **Информация о группах участника**: панель, открываемая долгим нажатием на любого участника (**включая свою строку**), показывает его **серверные группы** и **канальные группы** (имена групп берутся из `servergrouplist` / `channelgrouplist` сервера, при неудаче — откат к `#id`, при большом числе групп раздел прокручивается отдельно; в своей строке отображаются только идентификация и информация о группах, бессмысленные для себя операции скрываются).
19. **Каналы с паролем**: в строке канала отображается иконка замка, по нажатию открывается поле пароля (в плавающем окне — встроенный ввод), после чего вход выполняется с паролем, больше нет «нажал — и ничего не происходит»; пароль не сохраняется, при ошибке по-прежнему反馈 через подсказку сервера.
20. **Смена временного никнейма в канале**: долгое нажатие на свою строку → «Изменить временный никнейм», через `clientupdate client_nickname` применяется сразу; действует только для текущего соединения, не записывается в файл идентификации, после переподключения восстанавливается никнейм, использованный при подключении.
21. **Статус: онлайн / отошёл / не беспокоить**: переключается индикатором статуса в нижней панели или панелью по долгому нажатию на себя, через `clientupdate client_away` + сообщение об отсутствии (настраиваемое, до 100 символов); «отошёл» — это только отметка, микрофон работает как обычно, а «не беспокоить» действительно отключает микрофон и блокирует удержание для разговора / удержание для шёпота / открытый микрофон до переключения обратно в онлайн; в списке участников у отошедших отображается значок луны, а панель по долгому нажатию показывает их статус и сообщение об отсутствии.

## Пояснение о подписи сборки на нескольких компьютерах

В проекте используется файл подписи `release.keystore`, что обеспечивает одинаковую подпись APK, собранных на всех машинах, и отсутствие конфликта подписей при установке поверх.

**В репозитории не хранится ни один пароль подписи.** Скрипт сборки читает параметры подписи в следующем порядке; если нет ни одного из них — откатывается на debug-подпись (на локальную разработку не влияет):

1. Переменные окружения `SIGNING_KEYSTORE_FILE`, `SIGNING_STORE_PASSWORD`, `SIGNING_KEY_ALIAS`, `SIGNING_KEY_PASSWORD` (используются в CI, см. ниже)
2. `keystore.properties` в корне проекта (для локального использования, исключён через `.gitignore`):

```properties
storePassword=ваш пароль хранилища ключей
keyAlias=ts6droid
keyPassword=ваш пароль ключа
```

Сам файл подписи также исключён через `.gitignore` и не будет отправлен на GitHub; при совместной работе на нескольких компьютерах достаточно скопировать `release.keystore` и `keystore.properties` в соответствующие места.

### Генерация нового файла подписи

Если нужно заменить подпись (например, для официального релиза), выполните в корне проекта:

```bash
keytool -genkey -v -keystore release.keystore -alias ts6droid -keyalg RSA -keysize 2048 -validity 10000
```

> ⚠️ Ключ подписи равнозначен идентичности приложения: **не отправляйте `release.keystore` или пароли в репозиторий или публичные каналы**. В случае утечки другие смогут подписать установочный пакет с той же подписью, что и у вашего приложения.

## Как выполнить облачную сборку (GitHub Actions)

**Пуш в ветку по умолчанию / ручной запуск**: автоматически выполняется сборка и запуск модульных тестов, создаётся `app-debug.apk` (необфусцированный, большой по размеру) для отладки, доступен для скачивания в **Artifacts** на странице Actions.

**Официальный релиз**: после пуша тега вида `v2.1.6-Han` файл [android-release.yml](.github/workflows/android-release.yml) автоматически:

1. Проверяет соответствие тега и номера версии приложения (чтобы забытый номер версии не сломал проверку обновлений внутри приложения)
2. Запускает модульные тесты
3. Собирает release APK с подписью сертификатом из Secrets репозитория
4. Проверяет подпись APK и печатает отпечаток сертификата в лог Actions
5. Архивирует `mapping.txt` (необходим для восстановления номеров строк в обфусцированных стек-трейсах)
6. Вычисляет SHA-256 и создаёт GitHub Release

В **Settings → Secrets and variables → Actions** репозитория нужно настроить: `SIGNING_KEYSTORE_BASE64` (Base64-кодировка хранилища ключей), `SIGNING_STORE_PASSWORD`, `SIGNING_KEY_ALIAS`, `SIGNING_KEY_PASSWORD`.
